# ADR 0002: Πολιτική ασφαλείας: HTTP headers και CSP χωρίς 'unsafe-inline' στα scripts

- **Κατάσταση:** Αποδεκτή (το [ADR 0005](0005-syndesi-me-google.md) αλλάζει το `frame-src` και το `Cross-Origin-Opener-Policy` για τη σύνδεση με Google)
- **Ημερομηνία:** 22 Οκτωβρίου 2026
- **Υλοποίηση:** τα headers μπήκαν με το [PR #18](https://github.com/nikoleta06/dese-kordonia/pull/18) (μεταφορά στο Cloudflare)· τα hashes των scripts με το PR του `csp-strict`
- **Αποφάσισε:** Νικολέτα Ακρίδα

## Πλαίσιο

Το site είναι στατικό (Eleventy) και σερβίρεται από το Cloudflare Workers. Δεν έχει δικό του
server για τις σελίδες, αλλά οι σελίδες μιλούν με εξωτερικές υπηρεσίες:

| Υπηρεσία | Για τι | Τι επιτρέπεται |
|---|---|---|
| Δικό μας API (`api.desekordonia.com`) | Λογαριασμός, σύνδεση, newsletter | Κλήσεις (`connect-src`) |
| Supabase | Μετρητής like | Κλήσεις |
| GoatCounter | Στατιστικά επισκεψιμότητας | Script (`gc.zgo.at`), κλήσεις, εικόνα |
| OpenStreetMap | Πλακίδια χάρτη αγώνων | Εικόνες (`img-src`) |
| Open-Meteo | Καιρός, αναζήτηση πόλης | Κλήσεις |

Υπάρχουν λογαριασμοί χρηστών (email, passkeys, κωδικός), άρα πρέπει να προστατεύονται κυρίως από:

- **XSS** (κακόβουλο script μέσα στη σελίδα, π.χ. από κείμενο που δεν φιλτραρίστηκε σωστά), που θα μπορούσε να κλέψει δεδομένα ή να κάνει ενέργειες στο όνομα του χρήστη·
- **διαρροή δεδομένων** σε ξένα sites·
- **clickjacking** (το site μέσα σε αόρατο iframe άλλου site)·
- **υποκλοπή** σε σύνδεση χωρίς HTTPS.

Μέχρι τώρα το CSP είχε `'unsafe-inline'` στα scripts, επειδή 24 πρότυπα έχουν scripts γραμμένα
μέσα στο HTML (περίπου 1.500 γραμμές· ανάμεσά τους η σύνδεση, ο λογαριασμός και η επαλήθευση).
Με το `'unsafe-inline'` το CSP δεν σταματά ένα script που θα κατάφερνε να μπει μέσα στη σελίδα,
που είναι ακριβώς η πιο συνηθισμένη επίθεση XSS.

## Επιλογές για τα inline scripts

| Επιλογή | Υπέρ | Κατά |
|---|---|---|
| **Α. Κρατάμε το `'unsafe-inline'`** | Καμία δουλειά | Το CSP δεν προστατεύει από XSS |
| **Β. Μεταφορά όλων των scripts σε αρχεία `.js`** | Το πιο «καθαρό» | ~1.500 γραμμές σε 24 σελίδες, οι μισές με διαφορετικά κείμενα ανά γλώσσα· μεγάλος κίνδυνος να χαλάσει η σύνδεση |
| **Γ. Nonces** (τυχαίος κωδικός ανά αίτημα) | Ευέλικτο | Χρειάζεται κώδικα στον server σε κάθε αίτημα· το site σερβίρεται ως στατικά αρχεία |
| **Δ. Hashes στο `_headers` ανά σελίδα** | Όλα στο header | Το Cloudflare ενώνει headers που ταιριάζουν σε πολλούς κανόνες, οπότε θέλει εξαιρέσεις για κάθε σελίδα· εύθραυστο |
| **Ε. Hashes σε `<meta>` ανά σελίδα, στο build** | Αυστηρό, αυτόματο, δεν αγγίζει τα scripts | Δύο σημεία πολιτικής (header + meta) που πρέπει να μένουν συγχρονισμένα |

## Απόφαση

Επιλέχθηκε η **Ε**. Η πολιτική ασφαλείας του site είναι η εξής.

### 1. HTTP headers για όλες τις σελίδες (`_headers`)

| Header | Τιμή | Γιατί |
|---|---|---|
| `Strict-Transport-Security` | `max-age=31536000` | Μόνο HTTPS για έναν χρόνο, ακόμα κι αν κάποιος γράψει `http://` |
| `X-Content-Type-Options` | `nosniff` | Ο browser δεν εκτελεί αρχείο με λάθος τύπο (π.χ. `.txt` σαν script) |
| `X-Frame-Options` | `DENY` | Το site δεν μπαίνει σε iframe (clickjacking)· μαζί με το `frame-ancestors 'none'` του CSP |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | Τα ξένα sites βλέπουν μόνο ότι ο επισκέπτης ήρθε από το desekordonia.com, όχι ποια σελίδα |
| `Permissions-Policy` | κάμερα, μικρόφωνο, πληρωμές, USB: κανείς· τοποθεσία: μόνο το site | Τοποθεσία μόνο για το «Χρησιμοποίησε τη θέση μου» του «Ρυθμός & Καιρός» |
| `Cross-Origin-Opener-Policy` | `same-origin` | Παράθυρα άλλων sites δεν έχουν πρόσβαση στο δικό μας |
| `Content-Security-Policy` | δες παρακάτω | Από πού επιτρέπεται να φορτώνει και να στέλνει δεδομένα η σελίδα |

### 2. Content-Security-Policy σε δύο επίπεδα

**Header (ίδιο για όλες τις σελίδες):** `default-src 'self'`, μόνο οι υπηρεσίες του πίνακα
παραπάνω, `object-src 'none'`, `frame-src 'none'`, `frame-ancestors 'none'`, `base-uri 'self'`,
`form-action 'self'`, `upgrade-insecure-requests`. Στα scripts έχει ακόμα `'unsafe-inline'`,
επειδή ένα header δεν μπορεί να έχει διαφορετικά hashes ανά σελίδα.

**`<meta http-equiv="Content-Security-Policy">` σε κάθε σελίδα:** το φτιάχνει το `.eleventy.js`
(transform `cspScriptHashes`) σε κάθε build. Περιέχει
`script-src 'self' 'wasm-unsafe-eval' https://gc.zgo.at` και ένα `'sha256-…'` για **κάθε inline
script** της σελίδας (και για τα speculation rules). Μπαίνει πρώτο μέσα στο `<head>`, πριν από
οποιοδήποτε script.

Ο browser εφαρμόζει **και τις δύο** πολιτικές: ένα script τρέχει μόνο αν το επιτρέπουν και οι
δύο. Άρα στην πράξη τρέχουν μόνο τα scripts από το ίδιο το site, το GoatCounter και τα inline
scripts που γράψαμε εμείς, με ακριβώς αυτό το περιεχόμενο. Ένα script που θα έμπαινε κακόβουλα
δεν έχει σωστό hash και μπλοκάρεται.

Λεπτομέρεια που μετράει: ο browser διαβάζει τις αλλαγές γραμμής των Windows (`\r\n`) ως `\n`
πριν υπολογίσει το hash. Το build κάνει το ίδιο, αλλιώς τα hashes δεν ταιριάζουν.

### 3. Τι μένει επιτρεπτό, συνειδητά

- **`'unsafe-inline'` στα styles:** πολλές σελίδες έχουν `style="…"`. Το ρίσκο από CSS είναι
  πολύ μικρότερο από αυτό των scripts· μπορεί να αφαιρεθεί αργότερα.
- **`'wasm-unsafe-eval'`:** το χρειάζεται η αναζήτηση (Pagefind, WebAssembly). Δεν επιτρέπει `eval()` σε JavaScript.
- **`worker-src 'self' blob:`:** για την αναζήτηση.

## Κανόνες από εδώ και πέρα

1. **Νέο inline script σε σελίδα:** δεν χρειάζεται τίποτα· το hash μπαίνει μόνο του στο επόμενο build.
2. **Ποτέ `onclick="…"`, `onload="…"` ή συνδέσμους `javascript:`.** Αυτά δεν καλύπτονται από
   hashes και θα μπλοκαριστούν. Τα events μπαίνουν με `addEventListener` μέσα σε script.
3. **Νέα εξωτερική υπηρεσία:**
   - κλήσεις (API) → στο `connect-src` του `_headers`·
   - εικόνες → στο `img-src`·
   - script από άλλο domain → στο `script-src` του `_headers` **και** στο `SCRIPT_SOURCES` του `.eleventy.js`·
   - αναφορά και στη σελίδα απορρήτου.
4. **Script που δημιουργεί άλλο inline script την ώρα που τρέχει** θα μπλοκαριστεί· τα δυναμικά
   scripts φορτώνονται από αρχείο (όπως το GoatCounter στο `main.js`).
5. **Το `<meta>` πρέπει να μένει το πρώτο στοιχείο του `<head>`.** Αν μπει script πριν από αυτό, δεν προστατεύεται.

## Πώς ελέγχεται

- **Headers:** `curl -I https://desekordonia.com/` ή [securityheaders.com](https://securityheaders.com).
- **Τοπικά, όπως στο Cloudflare:** `npm run cf:dev`.
- **Μπλοκαρισμένα scripts:** στην κονσόλα του browser εμφανίζεται «violates the following
  Content Security Policy directive» μαζί με το hash που περίμενε. Αν εμφανιστεί για δικό μας
  script, κάτι αλλάζει το HTML μετά τον υπολογισμό των hashes.
- Στη μετάβαση (22/10/2026) ελέγχθηκαν όλοι οι τύποι σελίδων στα ελληνικά και στα αγγλικά (αρχική,
  αγώνες με χάρτη, εργαλεία, άρθρα, σύνδεση, λογαριασμός, επαλήθευση, απεγγραφή, αναζήτηση, 404)
  χωρίς κανένα μπλοκαρισμένο δικό μας script. Ένα «ξένο» script που προστέθηκε δοκιμαστικά μπλοκαρίστηκε.

## Αναφορά προβλήματος ασφαλείας

Όποιος βρει πρόβλημα ασφαλείας στο site το στέλνει στο **hello@desekordonia.com**, όχι σε
δημόσιο issue στο GitHub, ώστε να διορθωθεί πριν γίνει γνωστό.

## Συνέπειες

**Θετικές**

- Το CSP πλέον σταματά πραγματικά επιθέσεις XSS με inline script, και στις σελίδες σύνδεσης και λογαριασμού.
- Κανένα υπάρχον script δεν άλλαξε· μηδενικός κίνδυνος να χαλάσει η σύνδεση από τη μετάβαση.
- Τα hashes ενημερώνονται μόνα τους σε κάθε build.

**Αρνητικές / κόστος**

- Δύο σημεία πολιτικής (header και meta) που πρέπει να μένουν συγχρονισμένα στα scripts από άλλα domains (κανόνας 3).
- Inline event handlers (`onclick`) δεν μπορούν πια να χρησιμοποιηθούν (κανόνας 2).
- Τα styles έχουν ακόμα `'unsafe-inline'`.
